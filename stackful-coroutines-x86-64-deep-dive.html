Cooperative Stack Switching on x86-64: A Register-Level Account

Thesis: a suspended computation is one machine word. Formal model, ABI obligations, executable artifacts, cost model and failure conditions.

1. Thesis

A coroutine is a continuation reified as a stack. This account argues that on x86-64 the whole reification fits in a single machine word: the saved value of rsp. Every other component of the suspended computation (locals, spills, callee-saved registers, the resume address) is reachable from that word by construction, and control transfer is one ret executed against a stack that did not produce it. No state-machine transformation, compiler cooperation or kernel involvement is needed; the compiler observes an ordinary call that merely returns late.

The claim is sound only because of the calling convention. Section 3 derives the minimal save set from ABI obligations instead of convenience, and Section 7 lists the conditions under which that derivation stops holding.

2. Formal model

Define a context as C = (sp, S), where S is a memory region and sp points into it. Let switch(a, b) denote: store rsp into a.sp, load rsp ← b.sp, restore registers from b, then rip ← M[rsp]. Correctness reduces to four invariants:

InvariantStatement
I1 Frame shapeAt sp lie k register slots followed by exactly one code address
I2 Dual orderThe pop sequence is the reverse of the push sequence, slot for slot
I3 ExclusivityAt most one context executes, and its rsp lies inside its own S
I4 AlignmentAt the first instruction of any entry function, (rsp + 8) mod 16 = 0
; frame for k = 3 (higher addresses first)
;   [sp + 24]  resume address   <- consumed by ret
;   [sp + 16]  rbx
;   [sp +  8]  rbp
;   [sp +  0]  r12              <- sp

A never-run context satisfies I1 by forgery: the frame is written by hand, so the first transfer into it is indistinguishable from a resume.

3. Obligations

The System V AMD64 ABI partitions registers into caller-saved (rax rcx rdx rsi rdi r8-r11) and callee-saved (rbx rbp r12-r15). A compiler already assumes every call destroys the former, so a routine that looks like a call may destroy them too. The obligation is therefore exactly the callee-saved set plus rsp, together with the control bits of MXCSR and the x87 control word. The save set is a consequence of the interface the compiler believes it is using, not a design choice.

This argument is closed under synchronous transfer only. Under asynchronous entry (a timer signal or interrupt) the interrupted code made no call, no register is dead, and the entire architectural state must be preserved, which is why preemptive frames are an order of magnitude larger.

4. The transfer primitive

switch:                 ; rdi = &outgoing_slot, rsi = incoming_rsp
    push rbx            ; 1. spill callee-saved registers onto the OLD stack
    push rbp
    push r12
    mov [rdi], rsp      ; 2. record where the old context now lives
    mov rsp, rsi        ; 3. the actual switch: we are on the NEW stack
    pop r12             ; 4. reload the new context's registers
    pop rbp
    pop rbx
    ret                 ; 5. pop rip: resume the new context

Step 3 is the only instruction that changes identity. Before it, every push went to the old stack; after it, every pop comes from the new one, and the pop order must mirror the push order exactly. Note the symmetry: the code that resumes a context is the same code that suspended another one, which is why a coroutine that has been suspended inside switch resumes right after its own call switch.

Forgery

Writing k zeroed slots and an entry address yields a context satisfying I1 without it ever having run. The entry address occupies the slot that a real suspension would fill with a return address into switch's caller.

6. Native implementation: NASM, System V, Linux

The production form saves all six callee-saved registers and establishes I4 explicitly.

; void ctx_switch(void **save_sp, void *new_sp)
global ctx_switch
ctx_switch:
    push rbp
    push rbx
    push r12
    push r13
    push r14
    push r15
    mov  [rdi], rsp
    mov  rsp, rsi
    pop  r15
    pop  r14
    pop  r13
    pop  r12
    pop  rbx
    pop  rbp
    ret

; void *ctx_make(void *stack_top, void (*fn)(void))
global ctx_make
ctx_make:
    and  rdi, -16            ; align the top of the stack
    sub  rdi, 8              ; fake return slot for fn (falls into a trap)
    lea  rax, [rel ctx_exit]
    mov  [rdi], rax          ; if fn returns, go to ctx_exit
    sub  rdi, 8
    mov  [rdi], rsi          ; resume address = fn
    sub  rdi, 48             ; six zeroed register slots
    xor  eax, eax
    mov  [rdi],    rax
    mov  [rdi+8],  rax
    mov  [rdi+16], rax
    mov  [rdi+24], rax
    mov  [rdi+32], rax
    mov  [rdi+40], rax
    mov  rax, rdi            ; return initial rsp
    ret

ctx_exit:
    mov  eax, 60             ; exit(0)
    xor  edi, edi
    syscall

At fn's first instruction rsp points at the ctx_exit slot, reproducing the state an ordinary call yields.

;
;   extern void  ctx_switch(void **save, void *to);

Cost model

The register traffic (six pushes, six pops, one store) is cheap. The dominant term is prediction: a ret whose target disagrees with the return-address predictor stack mispredicts, costing on the order of a pipeline flush. Some implementations therefore end with a register-indirect jmp, trading predictor pollution for loss of the hardware pairing check. glibc's swapcontext additionally issues a signal-mask system call per switch, which is why it is slower than the pure register swap by roughly two orders of magnitude. The kernel's __switch_to_asm follows the same push/swap/pop shape but also updates per-CPU state, thread-local bases and FPU state.

8. Part II: stack provisioning

A context is only as safe as the memory behind S. Static arrays are acceptable for a demonstration but not for a runtime: a coroutine that overflows writes into whatever the linker placed next to it, and the failure surfaces in an unrelated component. The standard construction maps the stack anonymously and revokes access to its lowest page, so overflow becomes an immediate fault at the faulting instruction instead of silent corruption. Because mmap is lazy, untouched stack pages cost no physical memory, which is what makes six-figure coroutine counts feasible.

; rax = alloc_stack(rdi = usable size, multiple of 4096)   returns top of stack
alloc_stack:
    lea  rsi, [rdi + 4096]      ; usable + one guard page
    xor  edi, edi               ; addr = NULL
    mov  edx, 3                 ; PROT_READ | PROT_WRITE
    mov  r10d, 0x22             ; MAP_PRIVATE | MAP_ANONYMOUS
    mov  r8, -1                 ; fd
    xor  r9d, r9d               ; offset
    mov  eax, 9                 ; SYS_mmap
    syscall
    mov  rdi, rax               ; guard page = lowest page
    push rax
    push rsi
    mov  esi, 4096
    xor  edx, edx               ; PROT_NONE
    mov  eax, 10                ; SYS_mprotect
    syscall
    pop  rsi
    pop  rax
    add  rax, rsi               ; base + usable + guard = top
    ret

Two operational consequences follow. First, the kernel limits the number of distinct mappings per process (vm.max_map_count, 65530 by default), and each guard page splits a mapping, so very large populations need pooled stacks or guard-less slabs. Second, stacks must be recycled rather than unmapped on every exit, since munmap takes the address-space lock and serializes otherwise independent workers.

9. Signals, the red zone and alternate stacks

The ABI reserves 128 bytes below rsp as a red zone that leaf functions use without adjusting the pointer. The kernel respects this on signal delivery by skipping it, but only on the stack it delivers to. Two hazards arise in a stack-switching runtime. A signal arriving while rsp lies inside a coroutine stack executes its handler there, so every coroutine stack must have headroom for a signal frame (over 2 KB with AVX-512 state) in addition to its own needs. And a handler that itself calls ctx_switch abandons a frame the kernel expects to unwind through rt_sigreturn. The robust policy is to install handlers with SA_ONSTACK on a dedicated sigaltstack, make them do no more than set a flag, and perform the actual switch from the scheduler loop.

10. Shadow stacks (Intel CET)

With user-mode shadow stacks enabled, every call pushes the return address on a second, hardware-protected stack and every ret compares the two. Our primitive breaks this contract by design: the ret in ctx_switch returns to an address that was never called from the current shadow stack, so the processor raises a control-protection fault. A correct runtime therefore maintains a shadow stack per context and swaps the shadow stack pointer together with rsp.

; fragment: saving and restoring SSP alongside rsp (requires CET-enabled target)
    rdsspq rax                  ; rax = current shadow stack pointer
    mov    [rdi + 8], rax       ; context record: +0 sp, +8 ssp
    ...
    mov    rax, [rsi + 8]       ; target SSP (points at a valid restore token)
    rstorssp [rax - 8]          ; switch shadow stacks via the token
    saveprevssp                 ; complete the token exchange

Runtimes that cannot allocate shadow stacks fall back to the register-indirect jmp variant, since only ret is checked. Recent Linux kernels expose map_shadow_stack for allocating them, and the choice between the two strategies is ultimately a policy decision about whether the hardening is worth its per-context memory.

11. Unwinding and debuggability

Exceptions and debuggers walk frames using DWARF call-frame information. A forged frame has none, so a backtrace from inside a coroutine either stops at the entry function or wanders into garbage. Two measures suffice: terminate the chain deliberately by placing a zero in the slot above the entry address and declaring the return address undefined, and annotate the switch primitive so a stop at any of its instructions still unwinds.

    .intel_syntax noprefix
ctx_entry_trampoline:
    .cfi_startproc
    .cfi_undefined rip          ; end of the unwind chain
    call  r12                   ; r12 = user function forged into the frame
    xor   edi, edi
    call  ctx_exit
    .cfi_endproc

ctx_switch:
    .cfi_startproc
    push  rbp
    .cfi_adjust_cfa_offset 8
    .cfi_rel_offset rbp, 0
    push  rbx
    .cfi_adjust_cfa_offset 8
    .cfi_rel_offset rbx, 0
    mov   [rdi], rsp
    mov   rsp, rsi
    pop   rbx
    .cfi_adjust_cfa_offset -8
    pop   rbp
    .cfi_adjust_cfa_offset -8
    ret
    .cfi_endproc

C++ exceptions must not propagate out of a coroutine's entry function, since there is nothing above it to catch them; the trampoline is the place to establish a catch-all that records the exception and hands it to the resumer.

12. A scheduler with intrusive queues

For N tasks the run queue should be intrusive and circular, so spawn, yield and exit are constant-time with no allocation. The task record places saved_sp at offset 0, which lets yield pass the task pointer itself as the save slot and finish with a tail call, so the primitive returns directly to the yielder's caller.

; task record:  +0 saved_sp   +8 next   (circular singly linked list)
; cur: pointer to the running task
yield:
    mov  rdi, [rel cur]         ; prev = cur, and &prev->saved_sp == prev
    mov  rax, [rdi + 8]         ; next
    cmp  rax, rdi
    je   .alone                 ; sole runnable task: nothing to do
    mov  [rel cur], rax
    mov  rsi, [rax]             ; next->saved_sp
    jmp  ctx_switch             ; tail call
.alone:
    ret

task_exit:                      ; unlink cur, then switch without saving
    mov  rdi, [rel cur]
    mov  rax, rdi
.find:
    mov  rdx, [rax + 8]
    cmp  rdx, rdi
    jne  .adv
    mov  rcx, [rdi + 8]         ; predecessor found: splice out
    mov  [rax + 8], rcx
    mov  [rel cur], rcx
    lea  rdi, [rel dead_slot]   ; saved sp of a dead task is discarded
    mov  rsi, [rcx]
    jmp  ctx_switch
.adv:
    mov  rax, rdx
    jmp  .find

The exit path must not free the stack it is currently running on; the dead task's stack is queued for reclamation by the next context that runs. Blocking primitives (channels, mutexes) extend the same structure: a blocked task leaves the run queue and is linked into the wait list of the object it waits on, and the waker splices it back.

13. Generators: value-passing between contexts

A generator is a coroutine whose yields carry a value to the resumer. Because switch touches only the callee-saved set and rsp, caller-saved registers such as rdx pass through it untouched and serve as a zero-cost channel. The sequence below yields squares and signals exhaustion with zero. Expected output: 1, 4, 9, 16, 25, then the sum 55.

start: mov rax, 0 mov [0x4fe0], rax mov [0x4fe8], rax mov [0x4ff0], rax mov rax, gen mov [0x4ff8], rax mov rdi, 0x100 mov rsi, 0x4fe0 mov rbx, 0 ; accumulator, preserved across switches next: call switch ; resume generator, value returns in rdx cmp rdx, 0 je done print rdx add rbx, rdx mov rdi, 0x100 mov rsi, [0x108] jmp next done: print rbx hlt gen: mov r12, 1 glp: mov rdx, r12 imul rdx, r12 mov rdi, 0x108 mov rsi, [0x100] call switch ; yield rdx inc r12 cmp r12, 6 jl glp mov rdx, 0 ; exhausted mov rdi, 0x108 mov rsi, [0x100] call switch hlt switch: push rbx push rbp push r12 mov [rdi], rsp mov rsp, rsi pop r12 pop rbp pop rbx ret

The defining advantage of the stackful design is that suspension is transparent to every function in the call chain, including third-party code that knows nothing about coroutines. Its defining cost is that the stack must be large enough for the deepest call made while suspended, which is a capacity-planning problem the stackless designs avoid by construction.

15. The same primitive on AArch64

The construction is architecture-independent; only the register file and the return mechanism change. AAPCS64 makes x19–x28, x29 (frame pointer) and the low halves of v8–v15 callee-saved, and ret branches to x30, so the resume address lives in a register instead of on the stack and must be saved explicitly. The entry point for a forged context is therefore stored in the x30 slot.

// x0 = &save_sp, x1 = new_sp
ctx_switch:
    sub   sp, sp, #160
    stp   x19, x20, [sp, #0]
    stp   x21, x22, [sp, #16]
    stp   x23, x24, [sp, #32]
    stp   x25, x26, [sp, #48]
    stp   x27, x28, [sp, #64]
    stp   x29, x30, [sp, #80]       // x30 = resume address
    stp   d8,  d9,  [sp, #96]
    stp   d10, d11, [sp, #112]
    stp   d12, d13, [sp, #128]
    stp   d14, d15, [sp, #144]
    mov   x9, sp
    str   x9, [x0]
    mov   sp, x1
    ldp   x19, x20, [sp, #0]
    ldp   x21, x22, [sp, #16]
    ldp   x23, x24, [sp, #32]
    ldp   x25, x26, [sp, #48]
    ldp   x27, x28, [sp, #64]
    ldp   x29, x30, [sp, #80]
    ldp   d8,  d9,  [sp, #96]
    ldp   d10, d11, [sp, #112]
    ldp   d12, d13, [sp, #128]
    ldp   d14, d15, [sp, #144]
    add   sp, sp, #160
    ret                              // branch to x30

Two differences deserve attention. The frame is 160 bytes against 48 on x86-64, because the floating-point callee-saved set is part of the ABI obligation and not optional. And sp must remain 16-byte aligned at every memory access when stack alignment checking is enabled, so the frame size and the forged top of stack must both be multiples of 16; on x86-64 the equivalent constraint is invariant I4.

16. Measurement methodology

Switch cost is easy to measure wrongly. The reliable protocol is a ping-pong between two contexts on a pinned core, timing a large number of round trips with serialized counter reads (lfence; rdtsc at the start, rdtscp; lfence at the end), discarding a warm-up prefix, and reporting the median. Three confounders matter: frequency scaling (fix the governor or convert with the invariant TSC rate), return-address misprediction (measure both the ret and the indirect-jmp epilogues), and stack placement (two contexts whose stacks alias in the L1 set index will measurably slow each other, so stagger stack bases by a few cache lines). A result of a few tens of cycles per switch on current cores is typical when the predictor cooperates, and a multiple of that when it does not; absolute figures depend on microarchitecture and must be measured on the target.

17. Part III: preemption as forced entry

Everything so far is cooperative: the running context volunteers a call, which is why a small register set suffices (Section 3). Preemption removes the volunteer. A timer signal interrupts code that made no call, so no register is dead, the flags are live, and the vector state is live. The kernel has already done the expensive part: it writes the complete interrupted state into a ucontext_t on the signal stack before the handler runs. A preemptive runtime can therefore avoid a second save format entirely by treating that ucontext_t as the frame, and switching contexts by exchanging the saved state inside it.

// handler installed with SA_SIGINFO | SA_ONSTACK, driven by setitimer(ITIMER_REAL)
static void on_tick(int sig, siginfo_t *si, void *uc_) {
    ucontext_t *uc = uc_;
    task_t *prev = cur, *next = prev->next;
    if (next == prev || cur_in_critical) return;      // nothing to run, or unsafe point
    memcpy(&prev->uc, uc, sizeof *uc);                  // save the interrupted context
    cur = next;
    memcpy(uc, &next->uc, sizeof *uc);                  // rt_sigreturn will resume next
}

The return from the handler goes through rt_sigreturn, which restores every register, the flags, the FPU state and the signal mask from the modified frame, so the "switch" happens inside the kernel's restore path and I1 to I4 hold by the kernel's construction rather than ours. Two conditions make this unsafe without discipline. A tick may arrive while the interrupted task is inside malloc or any other non-reentrant routine, so the runtime needs a preemption-disable counter that the handler honours. And a tick may arrive while the task is executing ctx_switch itself, in the window between loading the new rsp and completing the pops, where the stack and the register contents disagree. The counter must therefore also be raised across the primitive, or the primitive must be placed in a code range that the handler recognizes by comparing the interrupted rip and declining to switch.

18. Blocking primitives from the same frame

A channel is a queue plus two wait lists. A receive on an empty channel does not spin: it unlinks the current task from the run queue (Section 12), links it into the channel's receiver list and calls ctx_switch to the next runnable task. A send that finds a waiting receiver copies the value directly into the receiver's saved frame and relinks the receiver to the run queue. Direct handoff is where the register-passing trick of Section 13 generalizes: the value is delivered into a saved register slot of the blocked context, so the receiver observes it as the return value of its own recv call without any buffer.

; receiver blocked inside chan_recv; its saved frame (Section 2) has
;   [sp + 0 ... ] callee-saved slots, then the resume address
; direct delivery of a pointer-sized value into the slot that becomes rbx:
chan_send_to_waiter:            ; rdi = channel, rsi = value
    mov  rax, [rdi + 16]        ; head of receiver wait list
    test rax, rax
    jz   .enqueue               ; nobody waiting: buffer it
    mov  rdx, [rax]             ; waiter->saved_sp
    mov  [rdx + 16], rsi        ; overwrite the saved rbx slot
    mov  rcx, [rax + 24]        ; waiter->wait_next
    mov  [rdi + 16], rcx        ; pop from wait list
    mov  rdi, rax
    jmp  runq_push              ; make it runnable
.enqueue:
    ; ... append to ring buffer, yield if full ...
    ret

A select across several channels extends this with a per-task registration record on every channel involved and a single atomic "claimed" flag in the task, so exactly one wakeup wins, and the losers unlink themselves lazily when next encountered. The invariants carry over unchanged because blocking is only a scheduling decision; the context switch beneath it is the same sixteen instructions.

19. Migration across threads and the TLS trap

Running the scheduler on several threads with work stealing lets an idle worker take a runnable task from a peer. A stackful coroutine is migratable in principle, since its state is self-contained, but it carries a hidden dependency: thread-local storage. On x86-64 Linux, TLS accesses are addressed relative to fs, and compilers are free to compute the thread-pointer-relative address of a variable once and reuse it across calls, because within one function the thread cannot change. After a coroutine is suspended on worker A and resumed on worker B, such a cached address still refers to A's storage. The same hazard applies to errno and to any TLS-derived cache in libc. There are three defensible policies: pin each coroutine to the worker that created it, forbid TLS use inside coroutines, or route every switch through a non-inlined function that the compiler must assume clobbers the thread pointer. Only the first is fully safe against third-party code.

The steal itself is a scheduling problem with its own invariants: a victim's deque must be manipulated with the Chase-Lev protocol (owner pushes and pops at the bottom without atomics in the common case, thieves CAS the top), and a task must never be runnable in two queues. The per-task "claimed" flag from Section 18 doubles as that guard.

20. Executable artifact: mailbox handoff under a scheduler

This program combines Sections 5.3, 12 and 18 in miniature: a producer and a consumer share a one-slot mailbox at 0x300, each yields when it cannot proceed, and a main loop schedules them round-robin. 22. Part IV: memory ordering once contexts cross threads

On a single thread a context switch needs no fences: program order on one core is preserved, and the incoming context observes every store the outgoing one performed. The moment a task can migrate between workers, the hand-off becomes a publication problem. x86-64 follows the TSO model: stores are not reordered with other stores, loads are not reordered with other loads, and a load never passes an earlier load or an older store to the same address. The only reordering the hardware permits is a later load overtaking an earlier store to a different address. Two consequences shape the runtime. A release store and an acquire load are ordinary mov instructions, so publishing a task onto a queue costs nothing extra. And the only place a fence is required is where a store must be globally visible before a subsequent load, which is exactly the owner-take path of a work-stealing deque. Compiler barriers are still mandatory everywhere: TSO constrains the processor, not the optimizer.

23. A Chase-Lev deque in x86-64 assembly

Each worker owns a deque of runnable tasks. The owner pushes and takes at the bottom, which is uncontended in the common case; thieves steal from the top with a compare-and-swap. The layout keeps top and bottom on separate cache lines so that thieves and the owner do not bounce a shared line on every operation (Section 24). This version uses a fixed power-of-two ring; growth requires publishing a new buffer pointer and is omitted.

; deque record:  +0 top   +64 bottom   +128 buffer   +136 mask (size-1)

deque_push:                      ; rdi = deque, rsi = task (owner only)
    mov  rax, [rdi + 64]         ; b
    mov  rcx, rax
    and  rcx, [rdi + 136]
    mov  r8,  [rdi + 128]
    mov  [r8 + rcx*8], rsi       ; write the slot first
    inc  rax
    mov  [rdi + 64], rax         ; publish: a plain store is a release under TSO
    ret

deque_take:                      ; owner; returns rax = task or 0
    mov  rax, [rdi + 64]
    dec  rax
    mov  [rdi + 64], rax         ; b = b - 1
    mfence                       ; the one required store-to-load barrier
    mov  rcx, [rdi]              ; t
    cmp  rax, rcx
    jl   .empty                  ; b < t: deque was empty
    mov  r8,  [rdi + 128]
    mov  r9,  rax
    and  r9,  [rdi + 136]
    mov  rdx, [r8 + r9*8]        ; candidate task
    cmp  rax, rcx                ; flags were clobbered by the and
    jg   .got                    ; more than one element: no race possible
    lea  r10, [rcx + 1]          ; last element: race with thieves
    mov  rax, rcx
    lock cmpxchg [rdi], r10      ; top: t -> t+1 if nobody stole it
    mov  [rdi + 64], r10         ; restore bottom to t+1 either way
    jne  .none
.got:
    mov  rax, rdx
    ret
.none:
    xor  eax, eax
    ret
.empty:
    mov  [rdi + 64], rcx         ; undo the decrement
    xor  eax, eax
    ret

deque_steal:                     ; any thief; returns rax = task or 0
    mov  rcx, [rdi]              ; t (loads stay ordered under TSO)
    mov  rax, [rdi + 64]         ; b
    cmp  rcx, rax
    jge  .none                   ; empty
    mov  r8,  [rdi + 128]
    mov  r9,  rcx
    and  r9,  [rdi + 136]
    mov  rdx, [r8 + r9*8]
    lea  r10, [rcx + 1]
    mov  rax, rcx
    lock cmpxchg [rdi], r10      ; claim the top element
    jne  .none                   ; lost the race, caller retries elsewhere
    mov  rax, rdx
    ret
.none:
    xor  eax, eax
    ret

The protocol is the x86 specialisation of the algorithm proven correct for weak memory models by Lê, Pop, Cohen and Zappa Nardelli; on TSO the weak-model fences collapse to the single mfence in deque_take, which stops the owner's decrement of bottom from being reordered after its read of top. Removing it permits the classic failure in which owner and thief both return the last task, and that failure is rare and load-dependent, so no unit test will reliably find it.

24. Cache geometry

Three placement rules follow from the measurements of Section 16. First, anything written by one thread and read by others (top, bottom, a task's wake flag) sits alone on a 64-byte line, or false sharing converts every push into an invalidation storm. Second, the saved-sp slot belongs with the task record that the scheduler already touches, since it is written on every switch and read by the next one. Third, stacks should be staggered by a few cache lines modulo the page size, because identically aligned stack tops map to the same L1 sets and evict each other under ping-pong. None of these change correctness; they change whether the nanosecond-scale switch cost survives contact with a real workload.

25. Parking idle workers

A worker with no runnable task and nothing to steal must sleep, or the scheduler burns a core per thread. The standard primitive on Linux is futex, which sleeps only if a word still holds an expected value, making the check and the sleep atomic with respect to a concurrent wake.

; park(rdi = &flag): sleep while *flag == 0
park:
    mov  esi, 128                ; FUTEX_WAIT | FUTEX_PRIVATE_FLAG
    xor  edx, edx                ; expected value 0
    xor  r10d, r10d              ; no timeout
    mov  eax, 202                ; SYS_futex
    syscall
    ret

; unpark(rdi = &flag): set and wake one sleeper
unpark:
    mov  dword [rdi], 1
    mov  esi, 129                ; FUTEX_WAKE | FUTEX_PRIVATE_FLAG
    mov  edx, 1
    mov  eax, 202
    syscall
    ret

The lost-wakeup hazard lives one level up. A worker that scans all queues, finds them empty and then sleeps can miss a task pushed in between. The remedy is a two-phase protocol: announce "searching" in a shared counter, re-scan once more, and only then park; every producer checks that counter after pushing and wakes a sleeper if it is zero. Because the announcement is a store followed by a load of different addresses, it requires the same store-to-load barrier as deque_take.

26. The hand-off race: publishing a task too early

The most instructive bug in a multi-threaded stack-switching runtime has nothing to do with registers. When task A blocks it is placed on a wait list, then ctx_switch runs and stores A's rsp. If the task is published to the list before that store completes, another worker can wake A and resume it from a stale saved_sp, executing on a stack that A is still using. Invariant I3 fails, and nothing in the primitive detects it.

The fix is deferred publication: the blocking path records the task in a per-worker pending slot, performs the switch, and whichever context resumes on this worker runs a post-switch hook that completes the publication. By then the save is finished, so the release store that makes A visible is ordered after the store of its sp.

; worker-local: pending (task to publish after the next switch completes)

block_on:                        ; rdi = task, rsi = wait list
    mov  [rel pending_task], rdi
    mov  [rel pending_list], rsi
    call sched_next              ; picks the next runnable task, ends in ctx_switch
    ; resumed here later, on possibly another worker
    ret

post_switch:                     ; called by EVERY context right after ctx_switch returns
    mov  rdi, [rel pending_task]
    test rdi, rdi
    jz   .done
    mov  rsi, [rel pending_list]
    mov  qword [rel pending_task], 0
    call list_push_locked        ; the task is now safely visible to wakers
.done:
    ret

Every return path out of the primitive must invoke the hook, including the forged entry trampoline of a context that has never run: its first instruction is call post_switch, followed by the user function. Omitting that one call leaves newly created tasks' predecessors unpublished, and the failure appears only when a task blocks immediately before a fresh one is scheduled, which is a rare interleaving that load tests tend to miss.

28. rt.asm

A task record is 32 bytes: +0 saved_sp, +8 next, +16 stack_top, +24 spare. Slot 0 of the pool is the initial thread, which is why rt_init needs no stack allocation. The forged frame for a spawned task places fn at top-16 and the address of rt_exit at top-8; because top is page-aligned, at the first instruction of fn the value rsp+8 equals top, which satisfies I4 with no arithmetic. If fn returns, it lands in rt_exit exactly as a normal return would.

default rel
extern ctx_switch, alloc_stack
global rt_init, rt_spawn, rt_yield, rt_exit

    lea  rdi, [pool]
    mov  [rdi + 8], rdi          ; circular list of one
    mov  [cur], rdi
    mov  qword [ntasks], 1
    ret

rt_spawn:                        ; rdi = void (*fn)(void)
    push rbx
    mov  rbx, rdi
    mov  edi, 65536
    call alloc_stack             ; rax = top of a fresh stack
    lea  rcx, [rax - 8]
    lea  rdx, [rt_exit]
    mov  [rcx], rdx              ; return address for fn
    mov  [rcx - 8], rbx          ; resume address = fn
    xor  edx, edx
    mov  [rcx - 16], rdx         ; six zeroed callee-saved slots
    mov  [rcx - 24], rdx
    mov  [rcx - 32], rdx
    mov  [rcx - 40], rdx
    mov  [rcx - 48], rdx
    mov  [rcx - 56], rdx
    mov  rsi, [ntasks]
    inc  qword [ntasks]
    shl  rsi, 5
    lea  rdi, [pool]
    add  rdi, rsi                ; rdi = new task record
    lea  rdx, [rax - 64]
    mov  [rdi], rdx              ; saved_sp = top - 64
    mov  [rdi + 16], rax
    mov  rcx, [cur]              ; link in after the current task
    mov  rdx, [rcx + 8]
    mov  [rdi + 8], rdx
    mov  [rcx + 8], rdi
    pop  rbx
    ret

rt_yield:
    mov  rdi, [cur]              ; &prev->saved_sp == prev
    mov  rax, [rdi + 8]
    cmp  rax, rdi
    je   .alone
    mov  [cur], rax
    mov  rsi, [rax]
    jmp  ctx_switch              ; tail call: returns to the yielder's caller
.alone:
    ret

rt_exit:                         ; unlink cur and never return to it
    mov  rdi, [cur]
    mov  rax, rdi
.find:
    mov  rdx, [rax + 8]
    cmp  rdx, rdi
    je   .unlink
    mov  rax, rdx
    jmp  .find
.unlink:
    mov  rcx, [rdi + 8]
    mov  [rax + 8], rcx          ; predecessor skips the dead task
    mov  [cur], rcx
    lea  rdi, [dead_slot]
    mov  rsi, [rcx]
    jmp  ctx_switch              ; the dead stack is leaked here, see Section 12

31. Part VI: exceptions, unwinding and the frame chain

The primitive moves control without the compiler's knowledge, but exception handling, debuggers, profilers and garbage collectors all reconstruct control flow from metadata: the .eh_frame section. It is a sequence of Frame Description Entries, each covering an address range and describing, for every instruction boundary, how to compute the Canonical Frame Address and where each callee-saved register was spilled. The unwinder never inspects the stack for plausibility; it looks up the return address in .eh_frame_hdr (a sorted table, binary-searched), applies the FDE's rules to recover the caller's registers, and repeats. A forged frame is therefore invisible to it until the walk reaches it, at which point the walk needs an explicit answer to the question "what is above this?".

C++ exceptions use two phases. The search phase walks outward asking each frame's personality routine whether it has a matching handler, without changing any state. The cleanup phase walks again, running landing pads (destructors) and finally transferring control to the handler. If the search phase reaches the top without a match, _Unwind_RaiseException returns _URC_END_OF_STACK and std::terminate runs, before any destructor has executed. In a coroutine the "top" is the entry trampoline, because the marker .cfi_undefined rip from Section 11 declares the return address unrecoverable there. Consequently an exception escaping a coroutine entry function terminates the process, and the only place to stop it is a catch-all inside the trampoline.

32. Propagating an exception to the resumer

The semantically clean rule is that an exception leaving a coroutine is delivered to whoever resumes it next, as if the resume call had thrown. The entry wrapper catches everything, stores a std::exception_ptr in the task record, marks the task finished and performs its final switch; the resume function checks the slot after the primitive returns and rethrows on the resumer's stack, where a real handler chain exists.

// C++ side of the trampoline
struct Task { void *sp; void (*fn)(void*); void *arg; std::exception_ptr err; bool done; };

extern "C" void task_entry(Task *t) {
    try { t->fn(t->arg); }
    catch (...) { t->err = std::current_exception(); }
    t->done = true;
    switch_to_resumer(t);                 // never returns
    __builtin_unreachable();
}

void resume(Task *t) {
    switch_into(t);                       // returns when t yields or finishes
    if (t->err) { auto e = std::exchange(t->err, nullptr); std::rethrow_exception(e); }
}

The rethrow happens on the resumer's stack, so the two-phase walk proceeds through real frames with real FDEs and never meets the forged one. Cleanup of the coroutine's own locals has already run, because the catch-all sat inside task_entry, below every frame the coroutine created.

33. The exception globals problem

The Itanium C++ ABI keeps per-thread state in a __cxa_eh_globals structure, reachable through __cxa_get_globals(): a linked stack of currently caught exceptions and a count of uncaught ones. Both assume strict last-in first-out nesting of catch blocks on one thread. Stack switching breaks that assumption. If coroutine A yields from inside a catch block, its caught exception remains at the head of the thread's list; coroutine B then throws and catches its own, pushing and popping correctly, but when A resumes and its catch block ends, the runtime pops whatever is at the head, which may belong to B. The symptoms are a corrupted list, a double free of an exception object, or std::uncaught_exceptions() returning nonsense.

// Itanium ABI layout (stable, defined by the ABI document)
struct EhGlobals { void *caught; unsigned int uncaught; };
namespace __cxxabiv1 { extern "C" EhGlobals *__cxa_get_globals() noexcept; }

struct EhState { void *caught; unsigned int uncaught; };

inline void eh_save(EhState &s)    { auto *g = __cxxabiv1::__cxa_get_globals(); s = {g->caught, g->uncaught}; }
inline void eh_restore(EhState &s) { auto *g = __cxxabiv1::__cxa_get_globals(); g->caught = s.caught; g->uncaught = s.uncaught; }

// every switch becomes: eh_save(cur->eh); ctx_switch(...); eh_restore(cur->eh);  (cur is re-read after the switch)

The save and restore must bracket the primitive on both sides, and a fresh task starts with both fields zeroed. Runtimes that never suspend inside a catch block can skip this, but that is a property of the application, not of the runtime, so a general-purpose library has to carry the two words in every context record. Note that the structure pointer itself is thread-local, which reintroduces the TLS hazard of Section 19 for migrated coroutines.

34. Stack clash and the guard page

Section 8 bought overflow detection with a single 4 KiB PROT_NONE page. That defence assumes stack growth is gradual. A function that allocates a frame larger than one page in a single sub rsp, N can move the stack pointer past the guard into adjacent mapped memory without ever touching it, after which ordinary stores corrupt a neighbour. Compilers counter this with stack probing: every page of a large frame is touched in order, so the fault happens at the guard. GCC and Clang emit such probes under -fstack-clash-protection; hand-written assembly must do the same.

; NASM: decrement rsp by a constant, touching every page on the way
%macro PROBED_SUB_RSP 1
%assign pages (%1) / 4096
%assign rest  (%1) - pages * 4096
%if pages > 0
  %rep pages
    sub  rsp, 4096
    or   qword [rsp], 0          ; read-modify-write faults at the guard page
  %endrep
%endif
%if rest > 0
  sub  rsp, rest
  or   qword [rsp], 0
%endif
%endmacro

big_frame_fn:
    PROBED_SUB_RSP 40000         ; ten probed pages, then a partial one
    ; ...

Variable-size allocations (alloca, VLAs) need the same treatment in a loop, which is why the compiler-generated form is preferable wherever C is involved. Coroutine stacks are especially exposed, because they are small and packed densely, so a single unprobed frame is likely to land on another coroutine's live stack rather than on unmapped memory.

36. Garbage collection over suspended stacks

A collector that finds roots by scanning stacks treats each suspended context as a region [saved_sp, stack_top) and the running context as [current rsp, its stack_top). The primitive helps here incidentally: because it pushes every callee-saved register before recording rsp, a pointer held only in rbx or r12 at the moment of suspension is already in memory inside the scanned range, so no register dump is needed for suspended contexts. The running context's registers still have to be spilled, typically by calling the collector through a small assembly stub that pushes them.

Conservative scanning treats every aligned word in the range as a potential pointer and retains whatever it may point to; it is simple, language-agnostic, and leaks occasionally through stale stack slots. Precise scanning needs compiler-emitted stack maps per call site, which a hand-rolled switch cannot provide for the frames below it, so precise collectors usually require that all switches occur at known safepoints with a documented frame layout. Two further details matter. The region between the guard page and saved_sp is dead and must not be scanned, and scanning it on a freshly recycled stack would retain garbage; and a stack freed but not yet reused still contains stale pointers, so pooled stacks should be cleared or their scan range kept at zero.
